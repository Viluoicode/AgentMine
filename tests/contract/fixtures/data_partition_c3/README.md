# C3 independent artifact oracles

These are literal expected bytes specified before the C3 production renderer.
They are not snapshots generated by running DataWorker or its renderer.

- `cases.json`: the twenty C2 independently specified input/partition cases, plus
  four explicit artifact cases (formula/CSV quoting, canonical negative numeric
  strings, approved lookup provenance, nested missing/null presence).
- Per-case files: 87 literal expected artifacts; complete evidence has exactly
  clean.csv, clean.json, rejected.json and validation.json. Incomplete evidence
  has validation.json only.
- `sha256.json`: pre-implementation hashes of cases.json and the literal files.
  The manifest intentionally excludes this explanatory README.

Preparation used only Python standard-library JSON/CSV serialization of the
independently specified expected values and C2 oracle facts. It imported no
AgentMine code, did not run the worker, partition core or production renderer,
and did not regenerate expectations after production changes.

Canonical encoding: UTF-8 without BOM; JSON ASCII escapes, sorted keys, indent=2,
no trailing newline; compact sorted JSON in CSV provenance; CSV LF line endings,
minimal standard quoting, approved column order followed by _provenance.
Canonical numbers remain JSON strings. CSV prefixes an apostrophe for values
whose left-stripped first character is =, +, - or @; JSON keeps original values.
CSV empty cells require provenance to distinguish missing/null/blank input.

The fixtures assert artifact representation, not client acceptance or authentic
source verification. Provenance explicitly says caller_supplied_unverified.
Runtime/QA v2 guards remain enabled; C4/C5 are separate checkpoints.
